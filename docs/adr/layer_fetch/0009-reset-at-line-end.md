# The pointers are reset at the line end; nothing counts words

Revisions 1 to 3 moved a pointer to its line start + stride with the line's last word, which meant counting groups and words to know which word was last, saving the start at the first word, and (revision 3) a flag per pointer and a catch-up at `line_go` for lines that ended before their last word. Jon asked for the simple rule instead: a pointer just counts on as words are read, and at each `line_go` every pointer the ended line fetched is reset to its line start + stride (or back to the start on a repeated line), which is also the next line's start. Stride stays start-to-start, so vertical scaling and a mid-line scale change need nothing more from software. The resets are made one pointer a clock at the start of the blank (up to 25 clocks for retro68k's 24 pointers), every line; in exchange the first- and last-word logic and the catch-up go, and the core is about as small as revision 1. Which pointers are reset is decided by a used flag a pointer: a word read sets it, the reset and a pointer write clear it. So a plane that is not fetched does not creep by the stride, and a pointer written after its last read on a line (a split screen, as both machines' documents rely on) starts the next line as written; a first version judged "fetched" from the layer's groups, depth and `dma_en` and added the stride to any write made during the line, which both machines rejected in review. The frozen reference fetches still move pointers at the last word, so the lockstep rigs copy the core's resets into them and compare addresses, not pointers.
